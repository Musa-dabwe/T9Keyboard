Bug

Hard-coded greys instead of the shared palette

EmojiPickerView.kt's setupViews() literally does setBackgroundColor(Color.parseColor("#111111")) for the top bar and "#2B2B2B" for the recycler — both predate this pass's keyboard_background (#1A1A1A) and key_surface (#0D0D0D) tokens, so this panel doesn't match the rest of the keyboard.

#111111 (shipped)
#2b2b2b (shipped)
#1a1a1a (shared token)
Proposed

Route through the shared color resources

Replace both Color.parseColor(...) calls with ContextCompat.getColor(context, R.color.keyboard_background), matching what symbols_view.xml already does. Zero visual risk — it's a straight token swap, and it makes future palette/theme changes apply here automatically instead of needing a second edit.
